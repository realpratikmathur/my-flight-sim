# my-flight-sim — learning F´ by flying a simulated quadcopter

This repository is a **learning project**. The goal is to understand
[F´ (F Prime)](https://github.com/nasa/fprime), NASA JPL's flight software
framework, by building the flight software for a simulated quadcopter. The
quadcopter flies in a physics simulator that you watch in a web browser.

The F´ framework itself is **not modified**. It is pulled in, unchanged, as a git
submodule at `lib/fprime` (release **v4.4.1**). Everything we write lives in
`MyFlightSim/` (flight software), and later `sim/` (physics) and `web/`
(3D viewer).

## How to use this repository

Each feature is on its own branch. The branches are **stacked**: each one starts
from the previous one, so checking out branch N gives you features 1…N. Every
branch adds a guide in [`docs/learning/`](docs/learning/) that explains:

* which part of F´ the feature uses, with quotes from the F´ docs and the
  [FPP User's Guide](https://nasa.github.io/fpp/fpp-users-guide.html)
* which files to read, in what order
* how to build, run and test the feature yourself, and what you should see

| Branch | What it adds | F´ concepts | Guide |
|---|---|---|---|
| `main` | Empty project made by `fprime-bootstrap project` | Projects, the `lib/fprime` submodule | — |
| `feature/01-quadfsw-deployment` | The `QuadFsw` flight software deployment, generated by `fprime-util new --deployment` | Deployments, topologies, subtopologies, rate groups, the GDS | [01](docs/learning/01-project-and-deployment.md) |
| `feature/02-simlink-sim-clock` | Our first component, `SimLink`; the simulator becomes the system clock (200 Hz lock-step) | Components, port kinds (`guarded`), events/telemetry, throttling, FPP structs and serialization, `Drv.Udp`, buffer pools, init specifiers, unit tests | [02](docs/learning/02-simlink-and-sim-clock.md) |
| `feature/03-physics-viewer-motors` | Quadcopter physics + 3D web viewer; `FlightController` with `ARM` / `DISARM` / `MOTOR_TEST` (open loop: it lifts off, then tips over) | Port definitions with return values, hardware-abstraction ports, arrays/structs/enums, commands and command responses, queued components, rate group ordering | [03](docs/learning/03-physics-viewer-motors.md) |
| `feature/04-closed-loop-flight` | Closed-loop flight: `TAKEOFF`, `GOTO`, `LAND`, a geofence, and 16 tunable **parameters** saved in the parameter database | Parameters (`PRM_SET` / `PRM_SAVE` / `PrmDb`), command validation vs execution errors, events as a flight log, keeping algorithms out of components, testing with parameters | [04](docs/learning/04-closed-loop-flight.md) |

More branches will be added as the project grows (flight plans with command
sequences, Mars mode, fault protection, FPP state machines, pilot mode, ...).

## One-time setup

Requirements: Linux or macOS, Python 3.9+, git, CMake, a C++ compiler
(`g++` or `clang++`), and a web browser with WebGL for the 3D viewer. See *Installing F´ › System Requirements* in
[`lib/fprime/docs/getting-started/installing-fprime.md`](https://github.com/nasa/fprime/blob/v4.4.1/docs/getting-started/installing-fprime.md).

```bash
git clone --recurse-submodules https://github.com/realpratikmathur/my-flight-sim.git
```

```bash
cd my-flight-sim
```

```bash
python3 -m venv fprime-venv
```

```bash
. fprime-venv/bin/activate
```

```bash
pip install -r requirements.txt
```

From feature 03 on, the simulator also needs one extra package (`aiohttp`):

```bash
pip install -r sim/requirements.txt
```

This follows *Installing F´ › Working With An Existing Project*, which says:

> When using `git` and submodules, remember to run `git submodule update --init --recursive`

and

> Some projects ship their own `requirements.txt`.  Install using that file if it exists.

Our `requirements.txt` points at `lib/fprime/requirements.txt`, so you get exactly
the tool versions that match F´ v4.4.1 (`fprime-tools 4.4.0`, `fprime-gds 4.4.0`,
`fprime-fpp 3.4.0`).

> **Always activate the virtual environment** (`. fprime-venv/bin/activate`)
> in every new terminal before running `fprime-util` or `fprime-gds`.

Then check out the branch you want to study, e.g.:

```bash
git checkout feature/01-quadfsw-deployment
```

and follow its guide in `docs/learning/`.
